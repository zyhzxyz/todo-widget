# 计时、面板与回收站：独立测试验收

这轮先验收交互，**不要上传 Windows 原始记录**。以下只使用独立测试服务与合成任务；自动化、Windows 构建成功不等于原生真机或真实 QQ 提醒已经验收。

## 更新前后

1. 先停止正在运行的计时，等待保存确认；保留一份当前测试数据的 JSON 导出。
2. 管理员先在线备份并升级**测试 API**，保留原测试卷，不清空测试进度。正式 API 和 AstrBot 不随这轮 UI 更新启用或迁移。
3. 完全退出旧版（包括托盘），从功能分支本次成功的 Actions 下载 `todo-widget-windows`，解压后运行新的 `todo-widget.exe`。这是便携 EXE，不是安装器。
4. 保持原有测试 SSH 隧道，仍连接 `http://127.0.0.1:3211`，使用原测试 app token；会话关闭后可能需要重新输入 token。**不是**正式服务 `3210`，也不用重新导入合成数据。
5. 不删除 `%LOCALAPPDATA%\com.local.todo-widget`，不清理 WebView2/LevelDB，不把旧本地 JSON 导入服务器。

新版增加可恢复删除字段。**客户端与 API 应配套更新**；一旦产生回收站数据，不要用旧 EXE 打开这批本地记录或操作新版服务。旧客户端不理解这些字段，可能只读报错；旧本地版的规范化还可能丢失删除标记。需要回退时先导出并保留新版本数据，由管理员核对兼容性，而不是覆盖数据库。

## Windows 上逐项确认

| 项目 | 操作 | 应看到的结果 |
| --- | --- | --- |
| 浮窗暂停 | 对合成任务右键「开始计时」，约 5 秒后点浮窗「暂停」，再等约 5 秒 | 数字不再增加；不必在任务上右键 |
| 继续与保存 | 点「继续」，再计约 5 秒，点「停止」 | 浮窗关闭；新增计时约为两段运行时间之和，不计暂停时间 |
| 主窗口兜底 | 另开一段计时，使用主窗口底部「暂停计时 / 继续计时 / 停止并保存」 | 与浮窗状态一致，三个操作都有明确按钮；当前任务行也有暂停/继续按钮 |
| 主题与点击区域 | 计时暂停时切换主窗口颜色，再点浮窗按钮和按钮里的图标 | 浮窗跟随主题；按钮是点击，不会变成拖动；标题区域仍可拖动 |
| 面板互斥 | 连续点日历 → 搜索 → 设置 → 日记 → 回收站 | 同时最多一个工具面板；搜索栏不盖住任务；面板不压住顶部工具栏和底部计时 |
| 面板关闭 | 重复点同一个工具图标，或按 Escape | 关闭当前工具；切换工具会保留日记编辑内容，离线草稿在当前会话中保留 |
| 窄窗口 | 缩窄主窗口，再反复切换工具 | 顶部按钮换行、不跑出窗口；工具内容在自己的区域滚动 |
| 即时撤销 | 完成一个合成任务 | 底部出现约 12 秒的提示和「撤销完成」；点后回到原清单，说明/历史计时保留 |
| 长期撤销入口 | 等提示消失，点顶部垃圾桶或右下角「回收站」 | 「已完成」里有文字按钮「撤销完成」，不是隐藏右键操作 |
| 每日目标 | 在「已完成」选择目标的历史打卡日期，再点「撤销打卡」 | 只取消选中日期，不把历史记录误当作今天打卡；其他日期和计时保留 |
| 删除与重启恢复 | 删除一个合成任务，关闭并重新打开新版，再进回收站的「已删除」 | 任务、完成说明和计时仍在；点「恢复」即可恢复，不是物理删除 |
| 已完成任务恢复 | 将已完成任务删除后恢复 | 完成状态仍保留，回到「已完成」；想重新做可再点「撤销完成」 |
| 任务集恢复 | 删除有子任务的合成任务集，再恢复 | 恢复同一批删除的子任务；先前单独删除的子任务不会被误恢复 |
| 恢复与提醒 | 恢复一个以前设过提醒的任务 | 旧提醒不会补发；需要提醒时手动重新设置 |

**旧版本已经物理删除且没有备份的记录无法凭空找回**。新回收站从本次可恢复删除开始生效，没有自动导入或扫描旧磁盘文件。

## 同步是否实时

- 本机修改立即提交 API，并等待保存确认；遇到冲突不覆盖服务器，断网不自动双向合并。
- 其他设备或机器人产生的修改：客户端在可正常连接时**每 5 秒轮询**；窗口重新获得焦点、网络恢复时也触发刷新。网络延迟、后台节流或未处理的冲突会增加等待时间，不能理解成严格的 5 秒送达保证。
- 这是近实时刷新，**不是 WebSocket 推送**。测试时可在另一客户端或测试 API 新增合成任务，保持当前窗口不动，确认下一次轮询出现。
- 正在运行的秒表每 5 秒保留本机恢复检查点；**停止/完成后才把本次计时提交服务器**，不逐秒同步计时动画。
- QQ 提醒属于独立 worker，默认约每 15 秒检查一次，且必须启用测试配置、白名单并真实私聊绑定。不要为了 UI 验收直接启用指向正式 API 的机器人配置。模拟 OneBot 测试不代表真实 QQ 已收到消息。

## 可复现自动化

```bash
npm ci
npm run check:tauri-versions
npm run typecheck
npm run typecheck:server
npm run typecheck:tests
npm test
npm run test:server
npm run test:plugin
npm run test:tools
npm run build
python3 -m pip install -r tools/requirements-e2e.txt
python3 -m playwright install chromium
npm run test:ui -- --screenshots /安全的测试目录/ui-regressions
# 可选：实际 Docker/Compose 路径，使用独立镜像标签
# docker build -f deploy/Dockerfile -t todo-widget-api:ui-test .
# npm run test:ui -- --docker-image todo-widget-api:ui-test
```

脚本创建自己的随机凭据、临时端口和数据库，只清理自己创建的资源，不访问正式或持久测试数据。覆盖 280×320、320×560、900×760 的工具布局，真实 Chromium 交互、回收站重载、HTTP 轮询与原本地数据不被覆盖。原生事件单测严格区分 Tauri 的全局监听与指定窗口目标；截图里的浮窗使用模拟桥接，只用于主题/按钮视觉检查，仍需以上 Windows 实测。
